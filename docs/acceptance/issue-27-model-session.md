## The first receipt and the model's follow-up reasoning

- **exp-001** observed a flat result: `total_return` 0.0, 0 fills, 653/653
  cash signals, benchmark `total_return` 0.5560334717297764. The receipt showed
  every signal `window` had length 1 and container input ~1.5 KB: the engine
  supplied a one-session cross-section, so the model's ≥20-close gate could
  never fire. The model recorded the hypothesis as rejected but mechanically
  untested and used that fact to choose exp-002 (quote:
  “exp-001's signal records log a point-in-time cumulative total-return index
  per ETF … so exp-002 tested a stateless top-1 relative-strength rotation”).
- **exp-002** observed the declared equal-weight fallback: 653/653 targets were
  exactly 0.2 per ETF, because no total-return alias was exposed; `total_return`
  0.5582357785286716, fees 270.519, 3,105 fills, `return_delta` +0.2202 pp.
  The model explicitly recorded that the relative-strength hypothesis was
  **not tested**, not confirmed.
- After the trusted operator fixed the generated-Python window to a rolling
  60-session panel, the model chose **exp-003** from the fixed interface (quote:
  “With the fixed 60-session history panel … a top-2 rotation beats equal
  weight”). The exp-003 receipt shows `WARMUP_REQUIRED, required_sessions 60`,
  585 signals each with `window` length 60, and container input ~21.3 KB — the
  intended multi-session panel.
