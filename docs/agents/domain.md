# Domain docs

## Before exploring

- Read the root `GLOSSARY.md` when it exists.
- Read `GLOSSARY-MAP.md` instead if present, then consult the glossary for the relevant context.
- Read relevant architecture decision records in `docs/adr/`.

If these files do not exist, proceed without treating their absence as a problem. Create them only when domain terminology or a consequential design decision needs to be recorded.

## Use the glossary

Use the glossary's terminology in issue titles, hypotheses, test names, and implementation discussions. Surface conflicts with relevant ADRs instead of silently overriding them.

## Layout

This is a single-context repository. Keep the glossary at the root and ADRs under `docs/adr/`.
